runner.py (HUB-DESIGN sections 6, 10, 12): JOBS registry {job: (module, callable)}; a Runner(store, collector_config, ...) with: settings reload on every cycle (settings.json changes from the web UI apply without restart; collector_config.json reloaded when its mtime changes; cc.apply() overlays the pinned keys, then settings.validate), one worker THREAD per job (so a long Outlook scan never delays the SLA check), the in-process Outlook lock around Outlook jobs, the cross-process lock store.try_lock("job-<job>") held for the whole run, scheduled runs by interval and settings.is_active (work days, active hours, holidays; run-now ignores that), email_report by report.send_times (once per slot per day; catch up if the PC was busy and the slot passed less than 3 hours ago), run-now requests via store.consume_run_requests (passing ctx.options requested_by / send_mail / force), heartbeat updates (running, started_at, last_run_at, last_ok_at, last_status, last_error, last_summary, last_duration_seconds, next_run_at, runs_ok, runs_failed, host, pid, enabled) at start, end and every 30 s while idle, JobContext construction (mailer = OutlookMailer() or FakeMailer in dry-run, credentials = lambda kind, username: collector_config.get_password(cc, kind, username), log -> store.append_log(job, ...)), writing the snapshot ONLY for ok results with snapshot_data (store.write_snapshot with host/duration/date), history points (store.add_history_point + prune), exceptions inside a job converted to a failed JobResult with the traceback in the job log (never the password), graceful stop.
